# Assumptions and decisions log

Every non-obvious decision, with the reason. Newest at the bottom.

| # | Date | Decision | Why |
|---|------|----------|-----|
| 1 | 2026-11-10 | Compute tier = "C+": the Tier C plan executed on the 4 GB RTX 3050 (see HARDWARE.md). | 4 GB sits below Tier B's 6 GB floor; base encoders fit, large ones and 3B/7B LLMs do not. |
| 2 | 2026-11-10 | `.venv` is created from the existing conda env's Python 3.11 with `--system-site-packages` so the already-installed CUDA PyTorch (2.14.1+cu126) is reused instead of re-downloading ~2.5 GB. All other packages are installed inside `.venv`; `requirements.txt` pins everything. | Speed and disk; a clean machine follows the torch install line in requirements.txt. |
| 3 | 2026-11-10 | Translation backend = **facebook/nllb-200-distilled-600M** (CC-BY-NC-4.0), not IndicTrans2. | The IndicTrans2 repos on the Hub are gated (require accepting terms + `huggingface-cli login`). I must not log in. The code supports IndicTrans2 automatically once a token exists (`backend: auto`), see MANUAL_TASKS.md. A pure-Python re-implementation of IndicTrans2's `IndicProcessor` is included because the official toolkit needs MSVC to build. |
| 4 | 2026-11-10 | Dhoroni label mapping: `Neutral` -> None; `Positive` with Focus in {Climate Change, Global Warming} -> Favour; `Negative`, `Problematic` and other-focus `Positive` dropped. Only headlines + first sentence are used. | Inspection showed Dhoroni's "Negative" means *negative environmental news* (plastic, waste), not disagreement with the claim; mapping it to Against would inject label noise. Headlines are closest in length to comments. |
| 5 | 2026-11-10 | GWSD labels = majority of the 8 worker votes, kept only if the majority share >= 0.5. | The Bayesian probabilities are missing for many rows; majority vote is transparent and reproducible. |
| 6 | 2026-11-10 | ClimateStance label ids: 0 = None, 1 = Favour, 2 = Against. | Verified by reading samples (label 2 texts are explicit denial). |
| 7 | 2026-11-10 | The hand-written gold set and the lexicon baseline were written by the same author. The lexicon's gold-set score is therefore optimistic and is flagged as such wherever it is reported. | Honesty about test-set/lexicon coupling. |
| 8 | 2026-11-10 | Dev set contains only `original`/`translated` rows; Romanized, code-mixed and synthetic copies are generated from TRAIN groups only. | Early stopping / model selection should not be driven by synthetic text; robustness is measured on the gold set and the challenge suite instead. |
| 9 | 2026-11-10 | Default training data is Indic-only (hi/bn). English originals are written to `data/processed/train_en.csv` and used only in the cross-lingual ablation. | The task is Hindi/Bengali; English is an ablation. |
| 10 | 2026-11-10 | Near-duplicate threshold: MinHash Jaccard >= 0.85 on char 4-gram shingles, within language. | Standard, conservative; translations of one sentence across languages are kept together via `group_id` instead. |
| 11 | 2026-11-10 | `pandas.read_csv` must be called with `keep_default_na=False` (helper `stance.utils.read_data`), because the label string `None` is otherwise parsed as NaN. | Found during the first smoke test. |
| 12 | 2026-11-11 | Transformer fine-tuning freezes the word-embedding matrix (`model.freeze_embeddings: true`). | MuRIL (197k vocab) / XLM-R (250k) weights + AdamW states exceed 4 GB; on Windows CUDA silently spills into shared system memory and training slowed to ~8 s/step (a 3-epoch run would take 8 h). Freezing embeddings keeps everything in VRAM; the usual accuracy cost of this for classification fine-tuning is small. |
| 13 | 2026-11-11 | GPU jobs are run one at a time (baselines on CPU while a transformer trains). | Two GPU jobs on a 4 GB card starve each other (observed 2h+ for one epoch). |
| 14 | 2026-11-11 | Transliterated-copy baselines (e) use a fixed C (taken from their base model's nested CV) instead of their own inner grid search. | With doubled-length text, nested CV over 300k char n-grams exhausted RAM (1 GB free virtual memory), ran 5 h on one model and slowed the parallel GPU job ~15x. |
| 15 | 2026-11-11 | Negation-flip augmentation uses only 14 hand-approved flips (data/augmentation/negation_flips_reviewed.csv, 64 candidates reviewed, each with a note). | Rule-based flipping of training text was mostly wrong: in 50/64 short candidates the rest of the comment still argued the original side, and on long translated text regex flips rarely touch the stance-bearing clause. Using unreviewed flips would inject label noise. |
| 16 | 2026-11-11 | BanglaBERT is trained and scored on Bengali rows only; its gold/dev F1 (0.797 / 0.682) is over the Bengali half and is not comparable with whole-set scores. It is excluded from final-model and "best transformer" selection, which require both languages. | A Bengali-only model cannot serve Hindi input; comparing its bn-only score with two-language scores would overstate it. |
| 17 | 2026-11-11 | Seed runs whose DEV macro F1 is below 0.5 are reported as "failed to train" and shown separately in the seed-variance table (aggregates given with and without them). | MuRIL pair claim-bn seed 44 never left the majority-class solution (loss flat at ~1.05 for 3 epochs, never predicted Against): a known BERT fine-tuning instability (Mosbach et al., 2021). The rule uses dev only, so it does not peek at gold. |
| 18 | 2026-11-12 | Dynamic int8 quantisation is applied to the self-attention Linear layers only; the efficient model is chosen among {best sparse, hybrid, int8 transformer} by the same selection score as the final model; latency is timed on uncached text variants and the ensemble latency is the sum of measured member latencies. | Quantising every Linear collapsed MuRIL (gold 0.74 -> 0.33; also per-channel); the feed-forward output projections see activation outliers (Bondarenko et al., 2021). Attention-only int8 stayed within 0.017 mean probability of fp32 on an 80-item sample. The first build saved the collapsed int8 model as "efficient" unconditionally and under-counted ensemble latency (cached embeddings, two members omitted). |
| 19 | 2026-11-12 | The ablation keep/drop rule is applied as specified and reported, but no augmentation is folded into the final model. | Every "keep" verdict is within noise: transformer ablations are single-seed (seed std of gold F1 is 0.05-0.10, section 2 of reports/discussion.md); the sparse plus_negation_flip CV gain is +0.0002 (CV std 0.006); the sparse plus_synthetic_x3 CV gain (+0.074) is mechanical, since template rows are near-trivially learnable (OOF F1 0.94-0.99) and adding them inflates CV. Retraining the final model on noise-level gains would be selection on the test sets. |
